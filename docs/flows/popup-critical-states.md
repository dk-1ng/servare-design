# Popup critical states: coverage

- Status: draft
- Issue: #12
- Inputs: [state inventory](../discovery/state-inventory.md), [ADR 0005](../decisions/0005-popup-structure.md), [ADR 0006](../decisions/0006-popup-layouts.md), [core flows](core-flows.md)

Low-fidelity wireframes of the popup's critical states in the chosen layout B (48px thumbnail, two-line row, choices in the item view). Open [`popup-states.html`](../../prototype/wireframes/popup-states.html) with the dev server (`pnpm dev`); add `?lang=pt_BR` or `?lang=pseudo` for other languages. Every frame lists the inventory IDs it renders, the actions it shows and the ones deliberately absent. Facets of the media row that layout B already shows are covered by the ADR 0006 wireframes (`popup-b.html?scene=…`) instead of being redrawn.

## Rules the wireframes apply

- **Actions are only §3.1 triggers.** Retry is withheld for `ERR-PROTECTED`; a protected item never gets Download, Record, Choices or Retry.
- **`unknown-request` hides the control** and the copy promises nothing (no "keep" without Stop, "save it again" without Retry).
- **Cancel asks before discarding** a recording; Stop and keep needs no confirmation and is never adjacent to an unlabeled Cancel.
- **Focus after a control replaces itself** moves to the row's new primary control, or its status line when there is none (WCAG 2.4.3). Frames are static; the notes describe the intended behavior for #20.
- **Reconnecting** keeps the last lists; request controls become `aria-disabled` (focusable, presses ignored) and re-enable in place, with no focus move. The Downloads summary only navigates, so it stays operable. The same frame stands for refetching.
- **Main rows stay short:** the next step and 1-click controls only; failed rows take at most the one extra line of ADR 0006. Details and blocker shortcuts are item-view frames.
- **Choices never appears** on a protected item or on a job whose media left the page (those live in the Downloads view).
- **The Downloads summary is pinned** in every main-view frame with jobs, including empty and all-protected pages, and under notices (ADR 0005 §5).
- **Markup and notes cannot drift:** each frame declares the controls it shows and omits, and the page throws if its markup disagrees.

## Gaps and open points found while drawing

- For #20: the "end the other job" shortcut (Stop that recording and keep it, or Pause) and the technical Details live on the full job card of the item view, not on the main row (ADR 0005 §2). The main waiting row shows only the sentence and Cancel; the blocker keeps its own controls on its own row or card.
- A Cancel confirmation is drawn inline for recordings only; other jobs use the same pattern with their own wording (not drawn).
- For #20: on a failed protected row the step text and the Why disclosure repeat the same sentence; show only the disclosure.
- For #20: put the "Loading…" status outside the `aria-busy` scroll region, so screen readers announce it.
- Annotations around the frames are English documentation marked `lang="en"`, not localized UI strings; each popup frame carries the active language.
