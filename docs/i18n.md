# i18n

Strings live in WebExtensions `messages.json` files, so Servare can adopt them unchanged and swap `t()` for `browser.i18n.getMessage`.

## Rules

- No user-facing string in HTML or TypeScript. Add a key to `prototype/_locales/en/messages.json` and `pt_BR/messages.json`.
- Every key needs a `description` (context for translators) in every locale. Named `placeholders` must match across locales.
- Keys are `snake_case` (`[A-Za-z0-9_@]` only, per the format).
- Static markup: `data-i18n="key"` (text) and `data-i18n-attr="aria-label:key;title:key"` (attributes). Dynamic text: `t(key, substitutions?)` from `prototype/src/i18n/index.ts`.
- Pages call `await initI18n()` before setting `html[data-ready]`.
- `pnpm check:i18n` (part of `pnpm check`) verifies key and placeholder parity, descriptions, and that every key used in `data-i18n` or `t('…')` exists.

## Locales

`?lang=en` (default), `?lang=pt_BR`, `?lang=pseudo`. `pseudo` is built from `en`: letters accented, text padded ~40% with `~`, wrapped in `[ ]`. Use it to spot hard-coded strings and overflow. `initI18n()` sets `lang` (`pt-BR`, `en-XA` for pseudo) and `dir` on `<html>`.

## RTL-ready rule

Use logical CSS properties only: `margin-inline`, `padding-block`, `inset-inline-start`, `text-align: start`, `border-start-start-radius`. Never `left`/`right` or `margin-left`. Mirror directional icons (arrows, chevrons) with `[dir='rtl']`. No RTL locale ships yet; `dir` is already derived from the language.
